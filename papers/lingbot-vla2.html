§1 两分钟总览：作者真正押注了什么？

阅读路径

先看评测协议，确认“跨本体、OOD、动态预测”分别被什么证据支持；再回到三条设计主线：60k 小时数据、55D 统一动作、MoE + Dual‑Query。最后把论文消融翻译成参赛优先级。

背景VLA 在实验台上能做多任务，但真实部署要求更多机器人形态、更多自由度、长时程移动操作与未来状态判断。
直接依赖LingBot‑VLA 1.0；Qwen3‑VL 视觉语言骨干；Flow / diffusion action expert；DeepSeek‑V3 式无辅助损失路由；DINOv3、LingBot‑Depth；π₀.₅ 与 GR00T N1.7 基线。
具体失败场景不同机器人 action schema 不一致；脏轨迹与视频—状态错位污染监督；只对当前帧反应，难以完成未来几步才显现后果的操作；长任务常完成前半段却卡在精确放置或释放。
核心 insight实用 VLA 的瓶颈是“数据 × 本体 × 时序”的联合对齐，而不是只放大 VLM。这是对三组设计的综合解释，属于 inference。
效果与代价真机平均值优于基线，但绝对成功率有限；需要约 60k 小时预训练数据、外部深度 / 视频教师、6B 级模型、FSDP2 和高显存部署。
数据谱系90k h 机器人池 → 50k h 过滤后机器人数据；20k h ego 池 → 10k h 过滤 / 重建后手轨迹；另用 5M 视频 clips 训练 DINO‑Video 教师。
展开原文 · 核心 claim

“predictive dynamics modeling for improved temporal reasoning.”

— Abstract, PDF p.1
先别混淆两个模型

LingBot‑VLA 2.0 是本文的直接 VLA：视觉 / 语言 / 状态 → action chunk，并用未来表征作辅助监督。LingBot‑VA 2.0 是另一篇 Video‑Action 世界模型论文。本页所有数字只来自 VLA 2.0。

§2.2 证据强度：最强结论与不能外推的部分

闭环性GM‑100、移动操作与 RoboTwin 都是闭环 rollout；Dual‑Query 的展示本身只是表征可视化。
试验量移动操作明确每个 task-setting 15 trials；GM‑100 未写 trials / seeds / 方差；RoboTwin 指南写每任务 100 episodes，但未报告 seeds。
基线公平性论文给出 GR00T N1.7、π₀.₅、VLA‑1.0 数字，但没有完整披露同数据量、同算力、同后训练步数；因此不能把差值全归因于单一模块。
OOD 真实性未见对象类别是真 OOD；±10 cm 初始位姿是局部扰动。两者在冰箱任务中被混合，无法分解各自贡献。
跨本体展示多平台能力，但测试本体都在预训练列表中；它证明“一个预训练底座可适配多本体”，不是未见本体零样本迁移。
仿真 → 真机官方仓库同时给出仿真和真机流程，但不是同任务、同策略的成对 sim-to-real 实验。

可支持的最强结论：在作者给定的后训练与评测协议下，LingBot‑VLA 2.0 在两种已参与预训练的真机平台上总体优于列出的基线，并对局部初始位姿扰动保留一定长时程能力。

暂时不能支持：广义的 open-world 鲁棒性、未见 embodiment zero-shot、动态扰动恢复、以及 Dual‑Query 对最终成功率的独立因果贡献。

§3.1 60k 小时不是“收集量”，而是过滤后的训练量

上一节留下的问题

既然性能不能只归因于架构，数据到底做了什么？机器人池从 90k h 过滤到 50k h，ego 池从 20k h 过滤到 10k h；这意味着数据清洗本身就是模型的一部分。

ROBOT · 90k → 50k h
动作平滑 + 视觉 / 状态对齐
jerk 与速度 / 加速度 Z-score 超阈值即丢弃；静态信号占比 >95% 丢弃；URDF 回放投影由人工检查错位。
EGO · 20k → 10k h
从视频恢复可训练的手轨迹
VLM 先排除无交互与第三视角；SLAM + MANO 恢复手轨迹；有效手帧低于 20%、轨迹跳变或违背生理约束则丢弃。
LANGUAGE
自动 task / subtask 标注
Qwen3.6‑27B 把视频切成连续子任务，用 15 个操作 primitive + transit / idle / other 的闭词表描述动作，物体名保持开放词表。
VIDEO TEACHER
5M clips 训练 DINO‑Video
Internet + ego + robot clips；每样本 16 帧；因果时间注意力 + 3D-RoPE；这是额外的预训练成本。
比赛启示：如果你的数据量远小于 60k h，最可迁移的不是规模，而是过滤规则。先画每维 action/state 的速度、加速度、jerk 和静态占比，再核对多相机时间戳与机器人状态，比直接延长训练更可能减少灾难性样本。

§3.2 55D 统一动作空间：共享接口不等于共享控制规律

为什么现在谈 action schema

清洗解决“样本是否可信”，统一动作空间解决“不同机器人是否能进同一网络”。它把各本体映射到固定 55D 向量，缺失部位 padding；真正决定是否好学的仍是 action target、坐标系与归一化。

55D canonical state/action vector
字段维度表示比赛中最容易错的地方
arm.position14双臂 joint position 的最大槽位原始 slice 次序、左右臂拼接、绝对 / 相对 target
end.position14每臂 XYZ + quaternion，共 7D × 2四元数顺序、坐标系、相对旋转在当前代码中不支持
effector.position2双 gripper通常不做 subtract_state
hand.position12双手关节缺失手部必须正确 mask / pad
waist / head / base4 / 2 / 3全身与移动控制单位、速度 / 位置语义、控制频率必须与数据配置一致
reserved4保留位不要误把 padding 当有效监督
官方自定义数据指南要求 LeRobot v2.1 / v3.0；robot config 同时定义 state/action slice、camera key 和 norm stats。字段名、维度或相机名不一致会直接抛错。真实 AgileX 示例对 arm 使用 subtract_state: true，对 gripper 使用 false。

跟着一条训练样本走
1 / 5

1. 先统一接口

原始机器人 state/action 被 robot config 切片、拼接、padding，并使用与配置绑定的统计量归一化到 55D schema。

2. 插入两组任务 query

$Q_t$ 读取当前场景，$Q_{t+T}$ 在因果上下文中学习预判 action chunk 末端的场景。

3. 动作专家回归连续 action chunk

当前视觉、语言、机器人状态与加噪动作共同条件化生成过程；输出不是离散 action token。

4. 每个 action token 选择专家

共享专家保留通用控制先验，路由专家承载本体 / 任务 / 阶段的可变模式；论文不预先规定专家语义。

5. 用当前与未来 target 约束隐藏状态

教师只提供辅助 loss。未来帧不作为部署输入；如果代码误把 future target 泄漏到 action 路径，离线指标会虚高。

§4.2 MoE：让容量按 token 分配，而不是让所有动作都走同一 FFN

对第 $\ell$ 层第 $t$ 个 token 的隐藏向量 $u_{\ell,t}\in\mathbb{R}^{d}$，输出是共享专家加上被选中的 routed experts：

$$m_\ell(u)=E_\ell^{(s)}(u)+\lambda\sum_{j\in\mathcal{R}(u)}g_{\ell,j}(u)E_{\ell,j}^{(r)}(u)$$Eq. 2 · PDF p.8
逐项拆解
$u_{\ell,t}$
一个 action token 在进入 FFN 前的 $d$ 维表示。
$E^{(s)}$
共享专家，每个 token 都走，承载跨本体的公共控制逻辑。
$\mathcal{R}(u)$
用 $\operatorname{TopK}(\sigma(u^\top e_j)+b_j)$ 选出的专家集合。
$g_j$
只用未加 bias 的原始 sigmoid affinity 归一化；平衡 bias 不直接篡改 mixture 权重。
$\lambda$
routed output 的缩放系数。
手算例，非论文实验：三位专家原始 affinity 为 [0.82, 0.62, 0.21]，平衡 bias 为 [−0.10, +0.20, 0]。Top‑2 按 [0.72, 0.82, 0.21] 选择专家 2 与 1，但 mixture 权重仍按原始值归一化，约为 0.431 与 0.569。这样负载平衡改变“谁被选”，不伪造模型对专家的置信度。

§4.3 Dual‑Query：把“看见当前”与“预判 chunk 末端”分成两个槽位

令动作 chunk 长度为 $T$。$Q_t$ 对齐当前帧，$Q_{t+T}$ 对齐未来帧；两者分别接受深度 L1 和视频特征 MSE：

$$\mathcal{L}_{depth}=\|P_d(Q_t)-D_t\|_1+\|P_d(Q_{t+T})-D_{t+T}\|_1$$Eq. 8 · PDF p.9
$$\mathcal{L}_{video}=\|P_v(Q_t)-Z_t\|_F^2+\|P_v(Q_{t+T})-Z_{t+T}\|_F^2$$Eq. 9 · PDF p.9
CURRENT QUERY
现在的几何与运动状态
LingBot‑Depth target 强调深度几何；DINO‑Video target 带因果时间上下文，不是逐帧独立 DINO 特征。
FUTURE QUERY
动作执行后的未来表征
训练时从未来帧抽 target，推理时必须仅凭当前 / 历史 token 预测；它是 proxy，不是显式像素世界模型。
先预测：为什么 Dual‑Query 可能不能直接提升成功率？

辅助表征可能学会深度 / 视频特征，却不一定把信息送进控制所需的 action subspace。论文只给 Figure 13 的感知可视化，没有“去掉 current / future depth / future video 后真机成功率”的独立消融，所以机制合理但控制增益尚未隔离。

§5.2 长时程 OOD：对象变化比 ±10 cm 位姿变化难得多

比赛读法：不要只报最终 success。逐 subtask 曲线能定位第一次系统性失败发生在哪一步。冰箱任务的难点不是单纯导航，而是“位姿偏移 + 新对象类别 + 多次抓放”叠加；应分别做 object-only、pose-only、combined 三套验证。

§5.3 最值钱的消融：先改 target / normalization，再谈复杂架构

P0 · 最大已证实增益

绝对 joint → 相对 joint

33.7 → 55.0，+21.3 pp。相对 target 把全局姿态回归变成局部修正；原始标准差从约 0.80 降到 0.28。

P0 · 数据尺度保持

MeanStd 归一化

55.0，优于 MinMax 47.5 和 Q01–Q99 47.4。原因不是 clipping，而是后两者压缩了有效动态范围。

P1 · 任务依赖

Joint vs EEF

平均 55.0 vs 56.0 几乎持平；Barcode 偏 joint，Ketchup 偏 EEF。不要全局拍脑袋选一种。

P1 · 回归精度

L2 vs L1

平均 55.0 vs 46.4。多数局部修正适合 L2；接触丰富、长尾动作可能更偏 L1。

这些消融只在四项 GM‑100 真机任务上成立。官方 RoboTwin config 反而使用 absolute action、bounds_99_woclip 和 L1_fm；这不是矛盾，而是提醒你不能跨协议照抄。

§6.1 面向灵波具身挑战赛：先把分数损失最大的接口问题消掉

适用前提

下列路线以官方开源的 RoboTwin 2.0 / LeRobot 接口为锚。正式赛题规则未提供，所以把“必须核对赛方文档”的项放在第 0 步；其余是即使规则不同也成立的实验纪律。

锁死评测协议

记录任务列表、成功判定、episode horizon、相机顺序、action 频率、允许的外部数据 / 权重、推理精度和 GPU 限制。不要把录像 FPS 当控制 Hz。

先跑官方 checkpoint，不训练

固定 RoboTwin revision 13c3c47，先用 FP32 跑 1 个 task smoke，再跑 clean / randomized。保存每任务 100 episodes 的日志和视频，确认分数口径一致。

验证数据映射与 norm stats

抽 32 条样本逆变换，人工核对左右臂 slice、gripper、相机 key、单位和 padding；画 raw / normalized action 分布。错误 norm JSON 可以让训练 loss 正常、闭环直接崩。

建立 failure taxonomy

至少分成 grounding、reach / IK、gripper / contact、chunk timing、recovery 五类，并记录“第一次失败子任务”。优化目标是把失败从高频类别中移走，不是只盯总平均。

只做有证据的第一轮 ablation

若是真机 joint control，先试 relative joint + MeanStd + L2；若是 RoboTwin，先复现官方 absolute + Q99-no-clip + L1_fm，再逐项改单变量。每次保持同 seeds 与 episodes。

最后再动 MoE / teacher loss

确认 schema 与基线稳定后，才调 routed experts、Top-K、aux / z-loss、future depth / video loss。否则架构变化会掩盖数据管线 bug。

一周冲刺顺序

D1 环境 + 官方权重 smoke；D2 完整基线与失败分桶；D3 数据 / norm 审计；D4 action target / chunk / camera ablation；D5 训练与 checkpoint 选择；D6 randomized / OOD 回归；D7 固化提交镜像、日志和复现实验表。

§7.2 论文、项目页和代码的不一致 / 未对齐项

MOE SIZE
项目页 128 / Top‑8，release config 32 / Top‑4
可能分别对应预训练与后训练，但论文没有给数值，也没有正式解释这层映射。复现时以具体 checkpoint 随附 config 为准。
LOSS-FREE ROUTING
论文 loss-free，RoboTwin 默认有 aux + z-loss
README 明确说明如何切回 loss-free：移除两项损失并把 bias update speed 设为 0.00025。不要只看论文名词。
ACTION RECIPE
真机消融 ≠ 仿真默认
真机最佳是 relative + MeanStd + L2；RoboTwin release 是 absolute + Q99-no-clip + L1_fm。协议和数据分布不同。
SIM EVIDENCE
RoboTwin 数字只在代码仓库
它是 2026-07-25 之后的工程结果，不属于 arXiv v1 的 Table / Figure。页面已单独标为 code evidence。
这篇论文最薄弱的地方

核心系统同时改了数据、骨干、动作空间、MoE 和辅助监督，却没有把这些变化在最终成功率上逐一隔离。论文证明了“整套系统可工作”，但没有充分回答“哪一个模块贡献多少”。挑战赛里应反过来做：锁住官方基线，单变量实验，并用 per-task / per-failure 结果决定下一步。

与 VLA / Embodied AI 的联系

LingBot‑VLA 2.0 代表从“单本体 action head”向“跨本体 canonical interface + 稀疏动作容量 + 表征级未来预测”过渡的一条工程路线。它不像 Video‑Action 世界模型那样显式生成未来视频，而是把世界模型的价值压缩成 future query 的监督信号，换取更直接的部署路径。
