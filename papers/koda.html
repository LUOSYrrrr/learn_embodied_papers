§2.2 证据强度：最强结论与不能外推的部分

闭环性真机是闭环 VLA 执行；tracking table 是仿真 rollout 诊断。
试验量每任务/条件 20 次，四任务合并 n=80；但每训练配置只跑一次，没有跨 seed 方差。
基线公平性主要基线是同一 backbone 的 robot-only 与内部模块消融；没有与 HALOMI/EgoHumanoid 做端到端成功率对齐。
OOD 真实性相对 robot demos 未见，但人类训练数据覆盖；不属于完全未见类别或新任务组合。
跨本体未做。实验始终是 Unitree G1 + BrainCo hands；变化的是 controller，不是 morphology。

可支持：在同一目标本体和相机约定下，KODA 生成的对齐数据可以分别补充两种 whole-body controller 的数据集，并显著改善 human-covered 的 robot-OOD。

暂不能支持：任意人形本体通用转换、完全未见对象 zero-shot 泛化、或 KODA 必然优于 HALOMI/EgoHumanoid 的端到端结论。

§3.1 为什么 HALOMI / EgoHumanoid 不能直接 enter other controller datasets？

它们当然也是 ego-to-robot：都从人类第一视角示范得到机器人学习信号。区别不在输入，而在最终监督标签停在哪一层。

不兼容层为什么会冲突KODA 怎么处理
动作空间SONIC 是 64 维 body label + 12 维 hand；HEFT 是 29 关节 + 9 pelvis + 12 hand，共 50 维。从同一 canonical motion 分别 rollout，重新生成各自 action。
状态分布同一个参考运动，被不同 low-level controller 跟踪后，实际关节与姿态会有残差。用该 controller 的 rollout 记录实际 state，而非复制理想轨迹。
观测—动作配对人类画面中的手臂外观、相机运动与机器人执行不一致。把图像重建成 motion-aligned 的 robot onboard view。
数据 schema已有 robot demos 已按某个 VLA/controller 预处理；接口不一致时无法直接 co-train。最后一步做 controller-specific instantiation，匹配目标数据集 schema。
“data silo”不是说原始视频毫无复用价值，而是说现成的监督样本不能无损地换一个 action interface 使用。若重新做 retarget、仿真 rollout 和标签生成，本质上就在补 KODA 的这层转换。

§3.2 Canonical record：controller-agnostic，但不是 embodiment-agnostic

一条人类示范可写成：

$$e^h = (\{I_t^h, D_t^h, C_t^h, J_t^h\}_{t=1}^{T},\; \ell)$$

经过运动与视角对齐，KODA 得到目标机器人 (R) 的 canonical record：

$$e_R^{\mathrm{can}} = (\{I_t^R, q_t^R\}_{t=1}^{T},\; \ell)$$

再用控制器 κ 的生成器 (G_\kappa) 实例化：

$$e_R^\kappa = G_\kappa(e_R^{\mathrm{can}}) = (\{I_t^R,s_t^\kappa,a_t^\kappa\}_{t=1}^{T},\;\ell)$$
(I_t^R)按目标机器人相机姿态合成的 onboard image。
(q_t^R)目标机器人本体的可执行 whole-body configuration；这里已经固定为 G1 + BrainCo。
(s_t^\kappa,a_t^\kappa)由指定 controller rollout 得到的状态和控制标签。

同一 record → SONIC

输出 76 维动作标签：64 body + 12 hand；状态也来自 SONIC rollout。

同一 record → HEFT

输出 50 维动作标签：29 joint + 9 pelvis + 12 hand；状态来自 HEFT rollout。

回答你的第三个问题：KODA 目前能从同一份 canonical G1 数据生成不同控制器所需的数据，不能直接把它当成“为不同机器人本体生成数据”的已验证方案。换本体要重新做 URDF/关节映射、手部 retarget、相机外参、碰撞与动力学约束、rendering，并重新验证；论文没有做这个实验。

§4.2 Whole-Body Motion：为什么不是“把手腕轨迹 IK 一下”就结束？

人类胸前相机和双手只给出稀疏约束。直接 IK 容易产生不可平衡、不可接触、控制器跟不上的轨迹。KODA 先构造手部目标，再用全身优化把它变成动力学上可执行的 G1 motion。

  1. HAWOR：估计世界坐标下的 MANO 双手姿态。
  2. Position retargeting：映射到 BrainCo 手腕与手指参考。
  3. Contact-aware refinement：由 EfficientSAM3 物体 mask 与深度形成交互几何；没有可靠接触时保留初始化。
  4. ScaleBFM + SCO：将 torso 和双腕作为关键跟踪点，在 MJX 中滚动优化全身命令。
  5. Mink temporal IK：固定 SCO 的躯干/下肢结果，进一步压低手腕误差。

SCO 的本质可写成“从候选命令分布里反复采样，选择累计 tracking cost 最低的 elite，再更新分布”：

$$u_{t:t+H-1}^{(i)} \sim \mathcal{N}(\mu,\Sigma),\quad J^{(i)}=\sum_{\tau=t}^{t+H-1} c(x_\tau,u_\tau),\quad (\mu,\Sigma)\leftarrow\mathrm{Fit}(\text{elite})$$

论文配置：50 Hz、horizon 40、每轮 80 个候选、8 轮；全身阶段 10 个 elites。这里的公式是对 CEM/SCO 过程的概括，不是论文新推导。

§4.4 Controller-specific command generation：共享物理目标，不共享标签

KODA 把 canonical G1 轨迹当作共同的物理参考，再让 SONIC 与 HEFT 分别 rollout。两者共享 44 维状态 schema：29 维 body joints 与 3 维 projected gravity 来自各自 controller rollout；12 维 hand angles 来自几何重定向估计，并非执行器测得的手部状态。动作 schema 则直接不同。

补充：换控制器，究竟哪些东西可以复用？

“Controller-agnostic”是对最终部署接口而言，不是说数据生成过程完全不用控制器。Canonical motion 仍借助微调后的 ScaleBFM；canonical RGB、G1 形态、手型和相机也已经固定。将同一目标交给不同 controller，不等于原有观测—动作对无需重编译。

§5 审稿式结论：KODA 真正解决了什么，还差什么？

最准确的一句话：KODA 是一个数据编译器：把人类 ego episode 编译成与指定机器人运动和视角一致的中间表示，再面向每个 controller 编译出可 co-train 的状态—动作样本。
真正新且有用把 observation alignment 与 control-interface alignment 放在同一个 ego-to-humanoid 数据生成框架里；canonical record 明确了可复用边界。
最强实验信号两个控制器的 robot-OOD 都随人类示范规模明显上升，且 full view alignment / command SCO 消融幅度大。
跨本体缺口只验证 G1 + BrainCo；没有第二种 morphology、相机安装、手型或自由度。
统计缺口每配置单次训练；预算子集独立采样而非 nested，论文未给采样比例细节、seed 方差或置信区间。
接触缺口细粒度手—物交互仍不能完全复现，也不建模接触力；作者将 real-to-sim/contact modeling 列为未来工作。
比较缺口没有与 HALOMI/EgoHumanoid 在同一 VLA、同一 controller、同一任务下直接比较。
如果要把 KODA 真正扩成 multi-embodiment，最少还要验证什么？

至少需要第二种机器人形态，明确 canonical record 中哪些变量进入 embodiment-neutral task space，重新定义跨本体接触/可达性约束，并分别报告 view synthesis、controller rollout 和真机成功率。否则“可以适配”只是工程可行性推断，不是论文已经证明的结论。

展开释义 · limitation（非逐字引文）

当前方法没有完整建模接触力，也不能保证细粒度手—物交互被准确复现。

— 对 Limitations, p.11 的中文释义
阅读这篇时最容易混淆三件事：跨 controller ≠ 跨 embodiment；robot-OOD ≠ human-data OOD；仿真 tracking error ≠ 仿真任务 benchmark。把这三条边界守住，论文的价值和局限都会清楚很多。

与 VLA / Embodied AI 的联系

对 VLA / WAM，KODA 的产物是可训练的观测—状态—动作样本，不是可以忽略底层接口的万能人类数据。先冻结目标本体、controller checkpoint 和动作时间基准，再生成训练标签；换 controller 后重做标签与 rollout 验证，往往比只改动作头维度更重要。
