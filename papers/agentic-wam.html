AW-0：代码、未来视频与动作一起生成，代码究竟执行了吗？

Agentic World Action Models · Zhuoyang Liu et al. · UC Berkeley / NVIDIA / UPenn
arXiv:2610.30136v1 · 2026-10-21 · 50 页 · 核读：2026-10-23

一句话核心洞见

把可组合技能写成代码，与未来视频和动作块联合去噪，让动作拥有结构化的子任务条件。默认模式不执行代码；hybrid 才尝试调用技能，且有效代码不等于有效物理执行。

仿真
RoboTwin：80.8% Clean / 20.6% Random；hybrid 63.1% / 29.2%。
真机
8 个任务的平均分步 rubric score 71.1%，不是完整成功率。
数据
2,913.22 小时：机器人 1,919.30 + 人类 993.91；50 个技能。
推理
4 次联合去噪；5090 报告 0.23 s。无在线自我学习实验。

1 · 它要填补的是技能组织，不是又加一个聊天机器人

问题与前置概念

普通 WAM 可生成视觉未来与动作，却缺少“先固定包、再拉拉链”的显式组合结构；Code-as-Policy 有组合技能，但其手写感知/控制 API 的物理能力有限。AW-0 把两者接在同一个模型里，让代码成为可学习的中间条件，而不是把所有控制委托给脚本。

Figure 1 · 三路生成与两种执行模式

  1. 左边约 3K 小时人机数据先被标成子任务代码；下方标注系统产生 50 个可复用技能。不是测试时由编码 Agent 重新训练机器人。
  2. 中间 Code / Video / Action 三专家联合生成；右上 pure 直接执行动作块，hybrid 才会在代码与动作之间切换。
  3. 右边八任务包含夹爪与灵巧手，但论文为每个目标任务做后训练，不是一个未经适配的通用权重完成全部任务。
五问速读 · §1–2
背景视频先验与技能复用缺少联合接口。
卡点仅预测像素不能明确表达任务阶段；代码可组合却可能无法处理复杂接触。
关键改动离散代码、连续视频、连续动作共同去噪；模态有向 attention；自动技能标注。
依赖SDAR-1.7B、Qwen3-VL-2B ViT、Cosmos-Predict2.5-2B、Wan2.2 VAE、CaP 与机器人数据。
最强证据 / 代价代码表示与 mask 的内控消融有收益；需要约 3K 小时数据、额外代码标注与专家计算，仍容易受视觉分布变化影响。

2 · 主干：谁能看见谁，什么时候动作真的执行？

Figure 2 · 最重要的主干图：联合迭代而非先写完代码

  1. 当前图像同时进入 ViT 与 VAE；语言和历史代码提供语义/进度，机器人 state 提供本体状态。代码画布初始全 mask，未来 latent 和动作初始为噪声。
  2. 下左的 C→V→A 是模态块因果 mask：代码不读视频/动作流，视频可读代码，动作可读两者；每个专家内部允许双向。不要与 OneWM 的时间块因果混淆。
  3. 下右每轮固定最高置信度的一批代码 token，同时更新连续视频和动作。4 轮后再决定 pure 或 hybrid，不是按文字 token 自回归 128 次。
  1. 取当前三路图像、语言、本体 state，以及压缩的历史代码记忆。图像分别由 ViT/VAE 编码。
  2. 初始化 128 个 mask 代码 token、未来视频噪声、32 步动作噪声；真实观察保持干净。
  3. 4 轮联合生成：代码每轮固定 32 个最高置信 token，视频用 UniPC，动作用 Euler 更新。已固定代码不再改。
  4. 默认执行动作块；生成代码不作为 Python 运行，而是在迭代中条件化视频/动作表示。
  5. 拿新观察重规划。历史代码缓存压缩成 K 个可学习槽位；每个 episode 重置。文中没有完整给出 K 和训练历史替换概率 p 的数值。

28 层 MoT 的共同 attention 为 2048D、16 heads×128；代码/视频专家 hidden 2048，动作 1024。代码预训练 embedding、norm、FFN、词表头冻结，训练 attention 投影/调制；ViT 冻结、merger 可训。视频路径把原VAE换成冻结的 Wan2.2 VAE（48 channels），视频专家的输入输出投影重新初始化；动作专家从零开始。不要把“使用预训练专家”理解成所有主干参数都冻结。

3 · 六个公式与具体算例

统一记号：C 是代码，Z 是未来视频 latent，A 是动作；下标 0 表示干净目标，不是机器人第 0 帧。𝒞ₜ={Oₜ,L,Sₜ,Mₜ} 是当前图像、指令、状态和历史记忆。r 为代码 mask 比例；σ 是连续变量噪声水平，和环境时间 t 不同。以下数字为教学示例。

Eq.1–2 · 同一个条件下的三路目标

pθ(C₀,Z₀,A₀ | 𝒞ₜ)
(代码 logits, v̂ᶻ, v̂ᵃ)=Fθ(C̃ᵣ,Zσᵥ,Aσₐ,σᵥ,σₐ;𝒞ₜ)

logits 是各词的未归一化分数；v̂ 是连续 flow 速度。代码选择离散词，视频/动作更新实数，因此“joint”不是把三者都量化成语言 token。例：同一观察下输出“固定左侧再拉右侧拉链”的程序、拉链变化的图像 latent 和双臂位移序列。

Eq.3 · 连续流匹配

Xσ=(1−σ)X₀+σε；σ=γu/[1+(γ−1)u]，γ=5

X 表示视频或动作；ε 为同形状高斯噪声。视频原始 u 来自缩放 Beta(7,1)，动作来自均匀分布。u=.5 时 σ=2.5/3≈.833，更多训练点在高噪区。若 X₀=2、ε=0，输入为 .334，目标速度 ε−X₀=−2；生成沿 σ 从 1 到 0 积分。

Eq.4 · 离散 mask 语言学习

C̃ᵣ,ᵢ = [MASK]（概率 r），否则为 C₀,ᵢ；r~U[0,1]

只对被 mask 的位置计算交叉熵，并确保至少一个位置被 mask。例：pick(apple,right) 遮掉 apple/right 后，由图像、指令和其他可见代码补全；不是模仿任意不可见未来事件。15% batch 另有指令/程序条件 dropout，区别于目标位置随机 mask。

Eq.5 · 为什么视频噪声采样要混合？

q(σ)=α ppre(σ)+(1−α)U(σ)，α=.5

视频预训练偏高噪；动作与代码学习可能需要更清晰的未来特征。混入均匀采样增加中低噪声覆盖，但直接改变采样会改变目标，所以还有下一式的权重。

Eq.6 · 每种模态保持自己的目标分布

L = Eq[wᵥ Lᵥ + .5 w𝓰 Lcode + w𝓰 Laction]
wᵥ=ppre/q；w𝓰=U/q

实际权重截断到 4 并按 batch 均值归一化。例：某噪声区 ppre=1.6、U=1，q=1.3，则视频权重≈1.23，代码/动作≈.77；不是让所有模态同样偏好高噪。截断/有限 batch 使其成为稳定化的重要性加权，不应声称严格无偏。

检查：C→V→A 是否意味着部署必定先写完代码、再生成视频、最后生成动作？

不是。它约束每层 attention 的可见性；三路在同一组去噪迭代中逐渐更新。AR 是另一个独立对照，不能从箭头读出串行调用次数。

4 · 代码从哪里来？人机数据到底怎么用？

Figure 3 · Agentic annotation 是数据标注流水线

  1. 种子示范→编码 Agent 生成程序→协调者审计重复结构并接纳技能。技能必须跨至少两个任务出现，不能把一整个任务答案包装成技能。
  2. 技能库冻结后重标种子，建立 subtask→code 缓存；新片段只有接触事件或手运动证据匹配才复用。否则重新生成。
  3. YAM 用传感器的夹爪开闭事件作约束；人类视频没有同等传感器事件，依赖可视手运动。两类标签的可靠性不是天然相同。

5 · hybrid 的两个算法：有效程序也可能让表现变差

Appendix I / Algorithms 1–2，pp.43–44

模型同时给出代码与动作；仲裁器检查代码能否接管。这里的 valid 是语法、依赖和阶段检查，不是世界模型已证明它一定能成功。

  1. 阶段门：已完成阶段不重跑；不能回到更早已尝试阶段；失败次数受限。
  2. 依赖门：引用变量在 episode 的持久命名空间已定义；感知 API 结果可跨片段保存。
  3. 语法门：允许的语句、非空、有变化；失败的原样片段跳过。
  4. 若尝试执行：丢弃本轮直接动作块，即使代码抛异常也不再执行这块旧动作；重新观察再规划。否则执行动作块。
  5. 状态记账：算法以无异常返回标记阶段完成，但无异常不等于物体真的到位。需要物理结果监测的改进属于未来工作。

Figure 35 · hybrid：按阶段切换，而非同时执行两种命令

  1. 绿色段执行代码技能，紫色段执行动作专家。例子中接近/码放较结构化，折叠主要由连续动作完成。
  2. 一条成功展示不能证明门控最优；真实比较只在 YAM 折毛巾给出 84.4→90.6，灵巧手缺乏对应 CaP 系统。

7 · 附录 E：八套 rubric 到底奖励什么

Figure 24 · 长程任务的代码标注和评分不是同一件事

  1. 颜色连接时间段与代码阶段：分三次折叠、铺平，再按粉/棕/绿顺序堆叠。

8 · 核心 insight 的证据与反例

Figure 5 · 代码应放在 attention 的哪一侧？

  1. C→V→A 使视频在代码计划条件下演化，再给动作提供特征。V→C→A 则让代码只能在世界预测之后介入。
  2. 总体 full 为 71.1，无代码为 32.9；并非每一任务都由 C→V→A 获胜，换灯泡 V→C→A 为 77.1，高于 75.0。

Figure 6 · 0.23 秒到底包含什么

  1. 同一 RTX 5090 上，joint 0.23 s、AR 0.55 s、无 code 0.19 s；包括视觉编码、联合去噪、视频解码、动作后处理。
  2. 联合去噪相对 AR 约 2.39× 加速，但比无 code 增加约 40 ms。该延迟不等于底层伺服频率，也不保证连续物理执行不卡顿。

Figure 7 · 注释、技能调用和普通子目标各提供什么

  1. 完整代码与去注释、去技能、自然语言子目标比较。完整代码在八任务均优于去注释；七任务优于文字子目标。
  2. Deal Poker 去技能下降到 42.0，对照完整 58.3。结构化可复用调用可能比一句子目标提供更具体的操作组织，但消融没有证明代码是唯一有效表示。

代码流用 ViT 条件比用 VAE 条件平均 71.1 vs 55.6（Table 3），支持语义视觉特征有益；joint 比 AR 为 71.1 vs 54.5（Table 4），但灯泡 AR 79.2 高于 joint 75.0。不能把平均改进说成所有任务都改进。

Figure 29 · 选对技能仍可能传错参数

  1. 生成代码学到了擦拭循环和技能名，但 displacement 列表多了两个元素。
  2. 语法可解析不代表参数维度正确；这解释了为什么 code grounding 不能只看 token accuracy 或 parse rate。

Figure 32 · 在线代码也可能语义对、语法错
