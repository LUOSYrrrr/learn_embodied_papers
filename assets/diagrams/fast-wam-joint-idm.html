Q9 · Video Token 与 Action Token 怎样交互？

注意力可以理解为“带着问题，从允许读取的信息中取出相关内容”。Q 是查询，K 用于匹配，V 是实际读取的内容。Action Token 发出 Q，视频特征提供 K/V；遮罩决定哪些视频位置允许被读取。

Attention(Q, K, V) = softmax(QKᵀ / √d + M) V

M 在允许的位置取 0，在禁止的位置取 −∞。下表中的视觉 K/V 只是动作注意力的跨分支部分；动作 token 也能读取本动作分支。

模式动作能读到什么视觉信息？未来视频是否读取动作？
Base当前帧特征否
Joint当前帧与当前去噪阶段的未来视频特征否；视频 → 动作是单向信息流
IDM推理时，当前帧与已生成未来的特征否，先视频后动作

这里的详细可见性来自当前官方 main 的代码核对：Joint 只开放 action 查询行读取全部 video 键列，没有开放 video 查询行读取 action 键列。默认 video_attention_mask_mode=first_frame_causal、action_conditioned=false。这不意味着论文原文已经给出了每个细分 mask。

Joint 中谁发出查询？允许读取的视频／动作 token
当前帧 token当前帧
未来视频 token当前帧＋未来视频
动作 token当前帧＋未来视频＋动作

三类 token 还读取语言条件。术语要分清：video/action 之间是 MoT shared attention；读取文本编码器输出则是 cross-attention。共享注意力允许按 mask 跨分支取信息，不表示双向互读，也不表示两套 DiT 共用同一套参数。上面的 Q/K/V 是标准注意力的教学展开。

语言 cross-attention 中，Q 来自视频或动作隐藏状态，K/V 来自指令。例如同一画面下，“拿起杯子”和“推开杯子”会给两支网络提供不同的任务条件。

Q10 · 两个 DiT 怎样联合训练？

同一段机器人演示提供当前观测、指令、未来视频以及真实动作。视频和动作各自加噪、各自预测 flow，再把两个损失相加做一次反向传播。

L = L_act + λ L_vid

损失会更新哪些参数，取决于前向计算实际依赖了哪些分支。它不是按网络名字平均分配梯度。

  • Base：视频损失更新视频分支；动作损失更新动作分支，并可通过当前帧特征回传到 Video DiT。
  • Joint：动作读取当前和未来视频的隐藏特征，视频不读取动作。因此 L_vid 不经动作专家回传；L_act 更新动作专家，并可经其读取的视觉特征回传到视频专家。“同步去噪”不等于“两个损失都更新两个专家”。
  • IDM：视频预测学习“未来怎样变化”，动作预测学习“给定当前与未来，该执行什么动作”。论文使用真实未来 token 作为训练条件，并以 0.5 概率做噪声增强；推理改用生成未来。
Joint（当前默认 mask，视觉条件路径可微时）： ∇θ_video L = ∇θ_video L_act + λ ∇θ_video L_vid ∇θ_action L = ∇θ_action L_act

公式按两个专家的参数集合书写，不表示每个参数都有非零梯度。可见性已按当前官方代码核对；跨分支梯度还要求对应条件路径没有被 detach。IDM 是否对条件缓存 detach 属于具体实现细节，不能仅由论文确定。联合训练不要求每个样本先完整生成未来视频。

Q11 · Video 和 Action 如何使用 Flow Matching？

同一套公式处理两种目标：y* 可以是一段未来视频的 VAE latent，也可以是一段真实动作。τ 表示加噪程度，不是机器人轨迹里的时间。

y_τ = (1 − τ)y* + τε u* = ε − y* L_FM = E ‖û(y_τ, τ, 条件) − u*‖²

训练时抽取一个 τ，给目标加噪，让对应 DiT 预测这条“数据到噪声”的直线速度。推理从噪声 τ=1 开始，沿时间反方向走到 τ=0。

教学用 Euler 更新：y_(τ−Δ) ≈ y_τ − Δ·û

一维算例：真实值 y*=2，噪声 ε=10；τ=0.5 时 y_τ=6，正确速度是 8。往 τ=0.25 走一步，6−0.25×8=4，再往 τ=0 走便得到 2。实际任务中的 y 是高维张量，模型估计的速度也不是预先知道的。

模式推理时怎样使用 flow？
Joint同一轮预测视频与动作的速度，更新两种 noisy tokens，重复到完成。
IDM先跑视频的去噪循环；缓存预测未来的表示；再跑动作的去噪循环。
Base视频主干只编码当前帧一次，动作分支运行去噪循环。
